# 邻块回填上线 + 答案侧抖动的真正来源

> 2026-11-12 傍晚。承接 [fold-expand-2026-11-11.md](fold-expand-2026-11-11.md)。
> 上一轮离线验证「折叠 + 回填 = 0.681（+12.5pp）」，这一轮把回填**接进生产代码**，
> 并用答案侧指标验收。
>
> 结论三句话：
> 1. 回填实现完成、默认关闭（`KB_NEIGHBOR_EXPAND_ENABLED=false`），带「同章节才补」闸门；
> 2. **上下文 +10.4pp（概览），但答案侧概览 +2 点、细节 −2 点，总量持平**；
> 3. 答案侧此前所有 ±5pp 级结论**都在噪声里**——同一配置重跑，答案覆盖率差 15.3pp。
>    根因是生成用模型默认温度（Ollama 0.8）。固定 0.1 后两跑**完全一致**。

## 1. 实现

| 位置 | 改动 |
|---|---|
| `src/services/chunk_expand.py` | 纯逻辑：`neighbor_positions` / `same_heading_as_parent` / `merge_with_neighbors` |
| `src/services/milvus_search.py` | `fetch_chunks_by_positions`：按 `(document_id, chunk_index)` 精确补查，一次 query |
| `src/services/vector_store.py` | `expand_neighbors`：Document 层拼装、父块分数继承、失败降级 |
| `src/services/kb_retrieval_service.py` | 在 **截断到 TOP_K 之后** 调用；耗时/增量写进 trace timings |
| `src/services/pipeline/retrieval.py` | 相关性门禁**忽略回填块**（见 §4） |
| `src/services/milvus_search.py` | 折叠同时接进 `search_hybrid_multi`（此前只有单查询路径） |

配置：`KB_NEIGHBOR_EXPAND_ENABLED`（默认 false）、`KB_NEIGHBOR_EXPAND_BUDGET_CHARS`（默认 2000）。

三个接入期才会踩的坑，都用单测钉住了（`test_chunk_expand.py` 20 例、`test_neighbor_expand.py` 8 例、
`test_analyze_answer_gap.py` 10 例；后端全量 1899 passed / 117 skipped）：

1. **必须在截断之后**扩：邻块排在原地块后面，先补后截断等于全被截掉。
   离线脚本直接在探针结果上算，天然没这个问题——接进生产时这是第一个坑。
2. **相邻的两个原地块互为邻块**：不按位置去重就会补出重复块。切片主键是 uuid、每次重灌
   都变，所以用 `(document_id, chunk_index)` 当身份。
3. **门禁不能被复制分数带偏**：邻块的 rerank 分是**沿用父块**的，让它参与平均分等于
   用「复制过的分数」重新投票。门禁只看原始入选块，与回填前逐位一致（有对照测试）。

## 2. 补上闸门：物理相邻 ≠ 语义连续

无差别回填的实测代价（默认温度、24 题）：

- 「生产环境升级要注意什么」基线答案讲了 SIGTERM 与 graceful shutdown；回填后答案变成
  「配置项清单」，SIGTERM 丢了——邻块把注意力引到别的章节；
- 「改完告警规则怎么生效」基线答 `promtool check rules`，回填后变成「跑测试脚本」。

真正需要回填的场景**必然同章节**：优雅停机的连续步骤、被按行切开的同一张表。
所以加了 `same_heading_as_parent`：两侧 `heading_path` 都非空且不等就丢弃。
不做「前缀相同也算」的放宽——`7.3 监控指标` 与 `7.4 告警规则` 的前缀只有 `7`，
而 `# 部署` 是它们的共同前缀，前缀规则等于没闸门。

## 3. 上下文侧：+10.4pp，稳定可复现

24 题、生产 606 块、窗口 3。上下文覆盖率是**确定性**的（重跑逐位相同）：

| 配置 | 概览 | 细节 | 平均块数 |
|---|---|---|---|
| 关（基线） | 0.500 | 0.708 | 3.0 |
| 折叠 + 回填 2000 | **0.604** | **0.750** | 6~8 |
| 折叠 + 回填 1200 | 0.583 | 0.708 | 5~6 |

离线上是 0.500 → 0.681，线上只有 0.604：差在**预算**（离线那档是无限预算 2028 字符）
和相关性门禁（3 题上下文被整体判不相关）。

## 4. 答案侧：概览 +2 点、细节 −2 点，总量持平

固定温度 0.1 后重跑两遍（两遍逐位相同，见 §5），答案事实点池化（宽松口径）：

| 配置 | 概览 命中/总 | 细节 命中/总 |
|---|---|---|
| 基线（关） | 9/30 = 30.0% | 11/18 = 61.1% |
| 折叠 + 回填 2000 | 11/30 = **36.7%** | 9/18 = **50.0%** |
| 折叠 + 回填 2000（重跑） | 11/30 = 36.7% | 9/18 = 50.0% |

合计 20/48 → 20/48，**一个点都没多**。上下文涨了 10.4pp，答案侧只是把「概览的 2 个事实点」
换成了「细节的 2 个事实点」。

这解释了两件此前想不通的事：

- 为什么上一轮离线 +12.5pp 看着很漂亮，用户侧却没感觉：**检索指标和答案指标不同步**；
- 为什么「加宽窗口」「扩池」都无效：问题不在候选多少，在**上下文进得去、答案写不出**。

**因此默认关闭**。不是实现有问题，是答案侧收益没被证明——多塞 3~5 块要付噪声和 prefill，
换 0 个事实点不划算。要打开的话，前提是先把 §6 的转化率问题解决。

## 5. 答案侧抖动的真正来源：默认温度

同一配置（折叠 + 回填 2000、默认温度）**连跑两遍**：

| 指标 | 第一遍 | 第二遍 | 差 |
|---|---|---|---|
| 概览 上下文 | 0.604 | 0.604 | 0 |
| 概览 答案 | 0.340 | 0.493 | **15.3pp** |
| 细节 答案 | 0.542 | 0.583 | 4.1pp |
| 自信漏答 | 9/24 | 6/24 | 3 题 |

上下文逐位相同、答案差 15.3pp ⇒ 抖动来自生成采样。查配置：模型注册表是空的
（走 legacy 路径），`temperature` 没配 ⇒ `langchain_ollama` 用默认 **0.8**。

固定 `KB_ANSWER_TEMPERATURE=0.1` 后同配置两跑：概览 11/30 与 11/30、细节 9/18 与 9/18，
**逐位相同**。

这条比邻块回填重要得多：**它意味着 11-12 之前所有基于答案覆盖率的结论（含上一份
`answer-side-2026-11-12.md` 里「gap 0.181 / 0.167」「自信漏答 7/24」）都落在噪声带内**，
只能当作方向性参考，不能当作验收数字。

新增配置 `KB_ANSWER_TEMPERATURE`（默认 `None` = 保持线上行为），
生产是否改默认值不在本轮决定内——低温度让细节题少 1~2 个事实点，需要更多样本才敢定。

## 6. 生成侧：被否掉的第六个改法

评测能复现之后，先试最便宜的一个：在 `answer_generator.txt` 加一条
「多条相关要点逐条列出、不要合并省略」。同温度、开关全关、两跑：

| 配置 | 概览 | 细节 |
|---|---|---|
| 基线 T=0.1 | 9/30 | 11/18 |
| 加完整性要求 A | 9/30 | 10/18 |
| 加完整性要求 B | 8/30 | 10/18 |

**没有收益，细节还少 1 点**。已回滚，不留没证据的提示词。

于是「有料不写」的现状是：上下文 30%/61% 的事实点被写进答案，剩下 70%/39% 丢在生成侧。
提示词层面改不动，剩下的候选方向（都未验证）：

1. **上下文组织**：现在 6~8 块平铺，标题路径重复率高；改为按文档+章节聚合、去重标题；
2. **模型能力**：线上是 `qwen2.5:3b-instruct`，3B 模型在「多要点归纳」上本就有上限；
3. **分块粒度**：行级块只有 100~200 字符，模型难以从碎片里归纳出完整清单。

## 7. 复现

```bash
# 上下文侧（确定性，可反复跑）
docker exec -e KB_TABLE_FOLD_ENABLED=true -e KB_NEIGHBOR_EXPAND_ENABLED=true \
  -e KB_NEIGHBOR_EXPAND_BUDGET_CHARS=2000 backend-prod \
  python scripts/probe_answer_quality.py --kb <kb_id> --flush-cache \
  --save-answers --report /app/data/answer-quality-foldexpand.json

# 答案侧复核（严格 vs 宽松、池化多臂对比）
python scripts/analyze_answer_gap.py --questions data/eval_questions.json \
  --arms 基线=...json 对照=...json
```

两条都必须带 `--save-answers` / `--flush-cache`：前者是复核措辞差异的唯一依据，
后者不清会命中语义缓存（重跑直接拿旧答案，指标变 0）。
