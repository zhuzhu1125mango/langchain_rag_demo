# 检索基线报告 · 2026-11-02（90 题版）

> 一句话：**稀疏通道（BM25）在 78 篇语料、84 道有答案题上 hit_rate@5 = 0.869、MRR@5 = 0.739**。
> 制度题与产品参数题都 100% 命中，**失分的 11 道全部是口语化提问**。
> 这个数字不是产品效果，是**检索回归的地板**——它只测「能不能把对的那篇捞进前 5」，
> 不测生成的答案对不对。

## 1. 为什么做这个

此前评测集只有 **5 道题、12 篇语料**，hit_rate 恒为 1.0：任何改动都不会让它动，等于没有指标。

数据集在一天内改了四次规模与构成，顺序本身说明为什么最后是这个数：

| 版本 | 规模 | hit@5 | MRR@5 | 为什么又改 |
|---|---|---|---|---|
| 原始 | 5 题 / 12 篇 | 1.000 | — | 没有区分度 |
| 第一次扩容 | 58 题 / 72 篇 | 0.904 | 0.854 | 口语化题只有 8 道，1 道 = 12.5pp，通道对比没有统计意义 |
| 第二次 | 70 题 / 72 篇 | 0.828 | 0.775 | 口语化补到 20 道，稀疏通道的真实短板才暴露 |
| **本报告** | **90 题 / 78 篇** | **0.869** | **0.739** | **补「产品型号 + 字段」20 题——真实流量六成是这个题型，此前完全没覆盖** |

第四次扩容的依据不是「题不够」，是**分布不对**：翻生产 `request_traces` 的 82 条真实问题，
约 50 条在问「智星 X1 的某个参数」，而旧语料 72 篇全是制度文档，一篇产品手册都没有。
在一个与真实流量正交的语料上调优，数字再漂亮也没有意义。

## 2. 方法

| 项 | 内容 |
|---|---|
| 数据 | `backend/tests/evaluation/kb_eval_dataset.jsonl`（90 题）、`eval_corpus.jsonl`（78 篇） |
| 检索栈 | 与生产同一套中文 BM25：`pymilvus.model.sparse.BM25EmbeddingFunction` + jieba 分析器 |
| 粒度 | 文档级：一题取 Top-5，命中任一 golden 文档即算 HIT |
| 指标 | `hit_rate@5`、`MRR@5`、`recall@5`，另按题型拆分 |
| 无答案题 | 6 道（班车/年会抽奖/健身房/期权/食堂菜单/宠物），只统计 top1 分数分布，**不并入上面三项** |

题目构成（90 道）：

| 类型 | 数量 | 说明 |
|---|---|---|
| policy | 40 | 照着制度条目问，与语料用词接近 |
| colloquial | 20 | 口语化（「出去玩几天」而不是「请假」） |
| **exact_match** | **20** | **型号 + 字段（「智星 X1 有几个 USB 接口」），题干原样取自生产真实 traces** |
| multi_hop | 4 | golden 两篇 |
| no_answer | 6 | 语料里确实没有，用于观察分数通道能否区分 |

语料 78 篇：12 篇原始 + 48 篇制度文档 + 12 篇近义干扰
（旧版已废止制度、境外差旅、日常报销、弹性考勤、分级草案、热修复…）+ **6 篇产品文档**
（X1 规格书 / X1 运维手册 / 保修政策 / 安装指南，另含 **X1 Pro 与 X2 两个近型号干扰**，
型号只差一个字符、数值全不同）。

## 3. 结果

```
hit_rate@5 = 0.869    mrr@5 = 0.739    recall@5 = 0.869
有答案 84 题 / 无答案 6 题 / 语料 78 篇
单题排序耗时 p50 = 0.26ms  p95 = 0.47ms（纯本地 BM25 打分，不含向量库/网络/LLM）
```

按题型拆开，结论比总分清楚得多：

| 子集 | 题数 | 命中 | 说明 |
|---|---|---|---|
| 制度问法（policy） | 40 | **40（100%）** | |
| 精确匹配（exact_match） | 20 | **20（100%）** | 但 4 道排在第 4–5 位，拉低 MRR |
| 多跳（multi_hop） | 4 | 4（100%） | |
| 口语化（colloquial） | 20 | **9（45%）** | 全部 11 道失分都在这 |

**两个数字必须一起看**：加精确匹配题后 hit 从 0.828 升到 0.869，MRR 却从 0.775 **降**到 0.739。
不是退化——BM25 能捞到 X1 的规格书，但常被 X1 Pro 挤到第 4–5 位，因为
「X1」也是「X1 Pro」的子串，而 X1 Pro 那篇更长、字段更全、token 更多，BM25 给它的分更高。

> 40/40 与 9/20 的对比是这份报告的核心：**在「知道该查什么词」的前提下，BM25 已经够了；
> 用户的真实问法才是瓶颈。** 而 MRR 的下降说明还有第二个瓶颈——**近义干扰下的排序**。
> 通道增量见 [channel-fusion-2026-11-02.md](channel-fusion-2026-11-02.md)。

**失分的 11 道（全部是口语化题）**：

| 问题 | 期望 | 实际 Top-2 |
|---|---|---|
| 我想出去玩几天，流程上要提前多久跟领导说？ | leave_policy | fin_budget_adjust / reimbursement |
| 自己先垫钱买的东西，怎么把钱拿回来？ | reimbursement | rd_rollback / ops_wifi |
| 在家干活要连什么东西才能进公司系统？ | remote_work | ops_password / meeting_policy |
| 年底发的那笔钱是怎么算出来的？ | bonus_policy | adm_team_building / zx_x2_spec |
| 刚进来头几个月算正式员工吗？ | hr_probation | rd_api_version / sec_data_class_draft |
| 想换个座位找谁？ | adm_seat | zx_install / zx_warranty |
| 部门聚餐的钱怎么报？ | adm_team_building | fin_petty_cash / adm_parking |
| 半夜系统报警谁爬起来处理？ | rd_oncall | ops_password / adm_visitor |
| 发版出问题怎么退回去？ | rd_rollback | zx_install / zx_warranty |
| 买台新电脑要走什么流程？ | it_equipment | hr_onboarding / fin_petty_cash |
| 想升职要满足什么条件？ | hr_promotion | rd_requirement_review / cs_refund |

失败原因一致：**问题里几乎没有能命中文档的实词**。BM25 只看词面，用户说「出去玩」，文档写「请假」。
（注意「想换个座位」「发版出问题」两题的 Top-1 变成了产品文档——语料扩充带来的新干扰，
不是退化：加入任何领域的新文档都会挤占一点排序空间。）

## 4. 无答案题：分数能不能代替拒答

```
top1 分数中位数：有答案 12.31 / 无答案 3.35 → 分离度 0.27
```

分离度 0.27 意味着无答案题的 top1 分数大约是有答案题的 1/4。看起来能设个阈值拒答，但**不能**：

- 无答案题里「公司是否提供上下班通勤班车？」的 top1 并不低，而有答案题里也有分数不高的；
- BM25 分数不归一，语料一扩充、文档一增长，绝对分数就整体漂移（本次扩语料后
  有答案题中位数就从 11.84 漂到 12.31），阈值会失效；
- 真正该拒答的判断在生成层（「检索到的内容是否足以回答」），检索分数只是它的输入之一。

所以这项只报告、不卡点。

## 5. 复现

```bash
cd backend
uv run python scripts/run_eval.py --report docs/benchmarks/retrieval-baseline-2026-11-02.json
uv run python scripts/run_eval.py --show-misses        # 只看没命中的题
```

CI 里由 `rag-eval` job 执行同一条命令；低于阈值直接失败：

| 阈值 | 默认 | 基线 | 说明 |
|---|---|---|---|
| `EVAL_MIN_HIT_RATE` | 0.83 | 0.869 | 留约 4pp（≈3 题）回退空间 |
| `EVAL_MIN_MRR` | 0.70 | 0.739 | 同上 |
| `EVAL_MIN_RECALL` | 0.83 | 0.869 | 同上 |

**调整顺序**：改数据集 → 重跑 → 在本目录留一份带日期的报告 → 再改阈值。
反过来（先调阈值让 CI 变绿）就是把指标变成装饰。

## 6. 这份基线的边界（别过度解读）

1. **只测检索，不测答案**：不涉及 LLM 生成、引用准确率、拒答质量；
2. **文档级、非 chunk 级**：生产按 chunk 召回再拼接；当前语料每篇 100–400 字，多数只切出 1 块，
   chunk 级评测做不出来（硬做就是「1 篇 = 1 块」的退化结果）；
3. **语料是合成的**：制度文档结构规整、表述一致，比真实企业文档「干净」；
   产品文档是按真实问法反推编写的，不是真实手册；
4. **只覆盖 sparse 通道**：同数据集上 dense / hybrid / rerank / 融合策略的对比与显著性检验
   见 [channel-fusion](channel-fusion-2026-11-02.md)；
5. **p95 不可当端到端延迟**：0.47ms 只是本地打分，不含 embedding、Milvus 往返与网络。

## 7. 下一步

1. **补到 150 题**：当前 84 题够判断「通道级」差异（15pp），不够判断「融合方式」（6pp）
   与「要不要重排」（3.6pp）——按不一致率反推需要约 100 题，留余量到 150；
2. **chunk 级评测**：需要先把语料写成真正的长文档（每篇 >2000 字），否则切不出多块；
3. **拒答评测**：构造 20 道无答案题，端到端看模型是否承认「知识库没有」，而不是靠分数阈值假装。
