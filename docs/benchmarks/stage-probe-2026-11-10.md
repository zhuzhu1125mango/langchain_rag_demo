# 检索逐级探针（2026-11-10）：泛问的损失不在候选池，也不在窗口

> 上一版探针（11-03）的前提已经失效：当时生产稀疏通道是死的，`sparse` 臂几乎无召回，
> 「概览型问题差」的结论混进了通道故障。稀疏索引重建后第一次能在**健康索引**上做三级拆解。

## 0. 结论

| 想说的 | 数据支持吗 |
|---|---|
| 候选池没捞到答案 | ❌ **不成立**：24 题里 23 题的答案片段在融合 top-20 内，21 题在 top-10 |
| 只要把窗口加宽就能救 | ❌ **不成立**：窗口 3 → 5 → 20，概览 **0.556 → 0.535 → 0.452**（单调更差） |
| 窗口 3 是必要条件 | ✅ 4 道零覆盖的答案片段全在融合第 **6** 名之后，窗口 3 下结构上不可达 |
| 真正的卡点是「选哪 3 块」 | ✅ 加宽后答案进了窗口（第 6/13/16 名），重排仍把它排到第 6/15/9，选不中 |
| 表格行级切片会吃掉名额 | ✅ 「监控指标/告警」一题：3 个名额被同一张指标表的 3 行占满，分数 0.97/0.968/0.961 |
| 「同表只占一席」能修好它 | ❌ **已被证伪**：同表折叠 0.452、章节去重 0.410，目标题仍是 0.00（见 §3.1） |
| 最终上下文 3 → 5 块能救 | ◐ 小幅：概览 0.556 → 0.577，细节 0.792 → 0.833（各约 1 题） |

**一句话：候选池够用；窗口 3 让答案根本进不来，但光加宽没用——卡点在重排的选择质量。**

## 1. 口径

| 项 | 值 |
|---|---|
| 语料 | `architecture.md` / `deployment.md` / `backup-restore.md` / `monitoring.md`，生产切分器 512/64 → **606 chunks** |
| 题量 | 24（概览 12 / 细节 12），事实点覆盖率口径（1 题 = 4.2pp） |
| 通道 | sparse = BM25 在**本语料**上 fit（健康）；dense = Ollama bge-m3；融合 = 等权 RRF k=60 |
| 重排 | `BAAI/bge-reranker-base`，CPU，max_length=256 |
| 生产实际配置 | 通道候选 20、**重排窗口 3**（`KB_HYBRID_RERANK_TOP_K=3`）、最终 3 块 |

语料 606 块与生产 532 块规模接近，但**内容不同**（这是项目文档，不是生产知识库），
所以结论是机制层面的，不是生产命中率。

## 2. 结果（事实点覆盖率，top-3 拼起来覆盖几个事实点）

| 配置 | 概览(12) | 细节(12) |
|---|---|---|
| **生产实际**：窗口 3 / 最终 3 | **0.556** | **0.792** |
| 窗口 5 / 最终 3 | 0.535 | 0.792 |
| 窗口 10 / 最终 3 | 0.535 | 0.792 |
| 窗口 20 / 最终 3 | **0.452** | 0.792 |
| 窗口 5 / 最终 5 | 0.577 | 0.833 |
| 窗口 5 / 最终 5 + 邻块回填 | 0.598 | 0.833 |
| 窗口 5 / 最终 5 + 整表回填 | **0.625** | 0.833 |
| 窗口 3 / 最终 3 + 整表回填 | 0.583 | 0.792 |
| 窗口 3 / 最终 3 + 目录块剔除 | 0.556（不变） | 0.792（不变） |
| 窗口 3 / 最终 3 + 多样性去冗余 | **0.410**（更差） | 0.792 |

> 生产实际是 **窗口 3**（`KB_HYBRID_RERANK_TOP_K=3`，代码里 `rerank_n = max(k, 该值)`），
> 不是配置默认的 5。也就是说重排只能给 RRF 已选出的 3 块**排序**，无法把第 4 名以后的
> 候选捞进来——四道零覆盖题的答案片段全在融合第 6 名之后，**在当前漏斗下结构上不可达**。

三条值得单独说：

1. **窗口越大越差**（概览 0.556 → 0.452）。宽窗口给了重排更多「看起来相关」的干扰项，
   而重排只输出前 3，多出来的候选没有变成覆盖率，只变成了竞争。
2. **目录块剔除没有收益**。11-03 的观察是「目录块拿 0.9556 挤掉真答案」，
   但在健康检索下它没进前 3，剔除它自然也不改变结果。
3. **多样性去冗余明显有害**（0.556 → 0.410）。概览题的答案本来就分散，
   去冗余把「不同章节但都含事实点」的块当成重复删掉了。

## 3. 四道零覆盖题：三种不同的失败

24 题里有 4 题在所有配置下覆盖率都是 0。逐题摊开后，它们不是同一种病：

| 题 | 融合名次 | 重排后答案名次 | 机制 |
|---|---|---|---|
| 系统由哪些部分组成，请求怎么流转？ | 16 | 6（窗口 20） | 重排分崩塌：top1 0.120，其余 **0.001**；答案块进了窗口也排不进前 3 |
| 监控哪些指标、有哪些告警？ | 13 | 15（窗口 20） | **同表三行吃满名额**：3 个 0.97 分全来自「7.3 监控指标」表，而事实点在「7.4 告警规则」表 |
| 换 Embedding 模型需要做什么？ | **32** | 窗口 20 内不存在 | 召回不到：题干用「换模型」，文档写 `embedding_migration` 脚本 |
| 备份恢复后要确认哪些事？ | 6 | 9（窗口 10） | 重排选了「演练记录」表格行（0.775），事实点是「恢复后必做」小节 |

三类问题需要三种修法，调一个全局参数解决不了：

- **重排分崩塌**（第 1 题）：top1 < 0.15 是模型在说「都不相关」。这种时候硬选 3 块，
  用户拿到的是自信的错答案。应该触发兜底（扩召回/换通道/明确说没找到），
  而不是继续往下走——这正是 11-09 那次 `kb_miss` 的同款形态。
- **同表挤占**（第 2 题）：表格按行切片对点查友好，对列举型问题灾难。
  需要的是**表格感知的选择**（同一张表只占一个名额，选中后回填整表），
  不是更大的窗口。
- **术语缺口**（第 3 题）：需要 query 改写（「换模型」→「embedding 迁移」），
  属于查询侧，和索引无关。

## 3.1 「按章节去重 / 同表折叠」已被证伪

直觉上最该做的事是「别让同一张表的三行占满三个名额」。探针里已有两个变体：
`diverse`（同一 `heading_path` 最多 1 席）与 `dedupe_table`（同一张表最多 1 席）。
逐题对比后，结论是**不但没修好目标题，还弄坏了正常题**：

| 题 | 基线 | 同表折叠 | 章节去重 |
|---|---|---|---|
| 监控哪些指标、有哪些告警？（目标题） | 0.00 | **0.00** | **0.00** |
| 系统由哪些部分组成（目标题） | 0.00 | **0.00** | **0.00** |
| 优雅停机怎么做 | 0.50 | **0.25** | **0.25** |
| 一致性巡检怎么跑 | 1.00 | 1.00 | **0.00** |
| 数据库迁移出错 vs 应用回滚 | 0.50 | **0.00** | 0.50 |
| 生产环境升级换版本 | 0.50 | **0.00** | **0.00** |

原因很直接：监控题的答案块在重排里本来就被打了低分（它排第 15），
换章节只是把「另一个低分块」提上来，不会把低分变成高分；
而「优雅停机/升级」这类题的答案本来就是同章节相邻几块，去重把它们拆散了。

**所以选择规则不是瓶颈，打分才是。** 任何下游的重排/去重都无法把低分块救回来。

## 4. 建议（按证据强度排序）

1. **不要调大 `KB_HYBRID_RERANK_TOP_K`。** 窗口 3→20 概览覆盖 −10.4pp，
   这是本次最硬的一条负面结论。现网 3 已经是覆盖最高的窗口，不要再调大。
2. **不要做「按章节/按表去重」。** 已测：整体 0.556→0.410 / 0.452，且不修目标题。
3. **整表回填是唯一非负变体**（窗口 3 下 0.583 vs 0.556，+2.7pp ≈ 0.6 题），
   但在噪声内，不值得为它改代码。
4. **`final_k` 3→5**：概览 +2.1pp、细节 +4.2pp，同样在 1 题量级。
5. **结论：现有全局旋钮都试过了，不要再调参。** 剩下的是重排对**结构化块**
   （表格行、代码块、目录块）打分偏低——四个目标题的答案块全部属于这类。
   这需要换模型或改重排输入，属于新实验，不是调参。

如果一定要继续，我建议的下一步不是改代码，而是**扩充评测集**：24 题的分辨率是
4.2pp，任何 1~2 题的改动都读不出显著性；先把题量做到 ~100 题（最好取自
`request_traces` 真实提问、跑在生产语料上），再决定要不要换重排模型。

## 5. 边界

- 24 题，1 题 = 4.2pp；两次运行的差异都在 1 题量级，不能当显著结论。
- 语料是项目文档（606 块），不是生产知识库（532 块）；机制可迁移，数字不可直接搬。
- 事实点覆盖率衡量「答到了几个点」，不衡量「答得对不对」；事实串本身也有字面性
  （第 3 题的 `embedding_migration` 就偏字面，可能低估了语义命中）。
